How a request is processed

  1. Client submits the request to the request-service (REST API).
  2. It is stored in the distributed storage: the coordinator picks the shard with sha256(key) mod 3 and writes both replicas.
  3. It is published to RabbitMQ (exchange erms.requests → queue matching.requests).
  4. A matching-service worker consumes it and picks the nearest available resource of the same type (within 50 km).
  5. The resource is assigned and both statuses are updated; without a match the request is retried later.
