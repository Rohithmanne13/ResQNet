=====================================================================================================================
 PART B - BUGS THE TESTS FOUND (BOTH FIXED)
=====================================================================================================================

  1. Simultaneous matching wrongly answered "no suitable resource".
     30 simultaneous POST /match against a resource with 20 free units -> only 5 matched, 25 got 409.
     Cause: claiming a unit gave up after 4 collisions with other matchers.
     Fix (common/resources.py): re-read and retry with a short random back-off until it succeeds or capacity is
     really gone. Now: exactly 20 matched, 10 refused.

  2. Matching the SAME request twice at once lost its unit.
     8 simultaneous POST /match of one request -> request "matched", but the resource's assigned list was [].
     Cause: a losing call released the unit the winning call had used.
     Fix (matching_service/matcher.py): on a conflict, release only if the request is not using the unit; after a
     successful match, confirm the unit is still held.

  Regression unit tests added for both; they FAIL on the old "Baseline V1" code and PASS now (27/27 unit tests).
